# JSSP Tensor-Based Training

This folder trains CNN models to select good solvers for Job Shop Scheduling Problem (JSSP) instances using **tensor representations** generated by [`src/data_generation/jssp_tensors`](src/data_generation/jssp_tensors/README.md).

Supported training tasks (via CLI):

- **classification** – predict the single best solver per instance  
- **multilabel** – predict all solvers that solve the instance within a time limit

Inputs are 2D matrices `(jobs, machines)` of processing times that are padded to fixed 3D tensors `(max_jobs, max_machines, n_channels)` before being fed to a CNN.

- [`cli.py`](src/training/jssp_tensors/cli.py) – command-line entry point for tensor training

## Inputs

The training CLI expects a CSV like the one generated by [`src/data_generation/jssp_tensors`](src/data_generation/jssp_tensors/README.md), for example:

- `data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv`

Required columns:

- `Image_Npy_Path` – path to a `.npy` tensor (usually a 2D matrix of processing times)
- `*_Runtime_s` – runtime per solver (e.g. `CBC_DEF_Runtime_s`)
- optionally `*_Score_S_rel` – solver scores (when using `--use_score`)

Tensor files may be:

- 2D `(jobs, machines)` – interpreted as a single duration channel
- 3D `(jobs, machines, channels)` – first `n_channels` from [`config.yaml`](src/training/jssp_tensors/config.yaml) are used

All tensors are padded or cropped to `(max_jobs, max_machines, n_channels)` as configured in [`config.yaml`](src/training/jssp_tensors/config.yaml).

## CLI usage (from project root)

Run the training pipeline via [`cli.py`](src/training/jssp_tensors/cli.py):

```bash
python -m src.training.jssp_tensors.cli --csv <csv_path> --task <classification|multilabel> [options]
```

### 1. Basic classification run

```bash
python -m src.training.jssp_tensors.cli \
  --csv data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv \
  --task classification
```

### 2. Basic multilabel run

```bash
python -m src.training.jssp_tensors.cli \
  --csv data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv \
  --task multilabel
```

---

### 3. Use custom config and override key hyperparameters

Start from [`config.yaml`](src/training/jssp_tensors/config.yaml) but override some options from the CLI:

```bash
python -m src.training.jssp_tensors.cli \
  --config src/training/jssp_tensors/config.yaml \
  --csv data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv \
  --task classification \
  --epochs 40 \
  --batch_size 64 \
  --learning_rate 0.0005 \
  --folds 10
```

---

### 4. Train on a subset of solvers

Assuming the CSV includes runtime columns like:

- `CBC_DEF_Runtime_s`
- `SCIP_DEF_Runtime_s`
- `HIGHS_DEF_Runtime_s`
- `CPLEX_DEF_Runtime_s`
- `GUROBI_DEF_Runtime_s`

You can restrict training to a subset via `--solvers` (names without suffix):

```bash
python -m src.training.jssp_tensors.cli \
  --csv data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv \
  --task classification \
  --solvers CBC_DEF,SCIP_DEF,CPLEX_DEF \
  --epochs 30
```

Multilabel with all five solvers:

```bash
python -m src.training.jssp_tensors.cli \
  --csv data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv \
  --task multilabel \
  --solvers CBC_DEF,SCIP_DEF,HIGHS_DEF,CPLEX_DEF,GUROBI_DEF \
  --epochs 30
```

If `--solvers` is omitted, all detected solver columns are used.

---

### 5. Use scores instead of runtimes

If your CSV includes `*_Score_S_rel` columns, you can base “best solver” selection on scores:

```bash
python -m src.training.jssp_tensors.cli \
  --csv data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv \
  --task classification \
  --use_score
```

---

### 6. Control output location and random seed

Send results to a custom parent directory and use a custom run name:

```bash
python -m src.training.jssp_tensors.cli \
  --csv data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv \
  --task classification \
  --out_parent results/jssp/tensors_custom \
  --run_name my_jssp_tensors_run
```

Set a specific random seed:

```bash
python -m src.training.jssp_tensors.cli \
  --csv data/jssp/datasets/jssp_cnn_data_tensors/ground_truth_jsp_generated_dataset.csv \
  --task multilabel \
  --seed 123
```

## Configuration (summary)

Key options live in [`config.yaml`](src/training/jssp_tensors/config.yaml):

- `data` – tensor shape (`max_jobs`, `max_machines`, `n_channels`), time limit, tensor path column
- `model` – CNN filters, kernel size, pool size, dense units, dropout
- `training` – epochs, batch size, learning rate, k-folds, early stopping patience, seed
- `output` – parent directory, run name, timestamp format, whether to append task name
- `tasks.classification` / `tasks.multilabel` – per-task output activation, loss, metrics, and multilabel threshold

The CLI can override several of these (`--config`, `--epochs`, `--batch_size`, `--folds`, `--learning_rate`, `--out_parent`, `--run_name`, `--seed`).

## Outputs

Each run creates a timestamped directory under `results/jssp/tensors` (unless overridden):

```text
results/jssp/tensors/<run_name>_<task>_YYYYMMDD_HHMMSS/
├── config.yaml               # effective config used
├── run_info.json             # CLI arguments, CSV path, timestamp
├── metrics_per_fold.csv      # per-fold metrics
├── metrics_summary.json      # aggregated statistics
├── <metric>_per_fold.png  # metric vs fold plot
└── fold_1/, fold_2/, ...     # per-fold predictions, metrics, plots
```

For metrics like `resolved_rate` and `AST_sec`, aggregation across folds is handled in [`training_loop.run_kfold`](src/training/jssp_tensors/training_loop.py:150) by reusing the evaluation logic from the image-based JSSP training module.

## Requirements

Main dependencies are shared with the image-based training pipeline and are listed in [`requirements.txt`](requirements.txt):

- Python 3.8+
- TensorFlow 2.x
- NumPy
- pandas
- scikit-learn
- Matplotlib
- PyYAML

Before training, make sure you have already generated the JSSP tensor dataset with [`src/data_generation/jssp_tensors`](src/data_generation/jssp_tensors/README.md) and that the CSV used in `--csv` exists and contains valid `Image_Npy_Path` entries pointing to `.npy` tensor files.
